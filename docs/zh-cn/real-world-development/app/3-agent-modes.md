我们先为项目添加了一项小功能，但更大的更改需要更完善的流程。GitHub Copilot app 可以融入组织现有的工作方式，确保以正确的方法构建所需功能。本课将开启一系列课程，带您体验典型的智能体驱动开发流程：从议题出发生成新功能，确保代码有效、功能符合预期，最终成功合并到项目中。

> [!NOTE]
> 后续功能开发过程中会继续使用同一个会话。通常，不同文件类型的工作会放在不同会话或 PR 中，但为帮助您聚焦核心概念，本研讨会会采用简化流程。

本课将：

- 根据 GitHub 议题开始新的智能体会话；
- 在 **Plan** 模式中明确需求；
- 使用 **Autopilot** 模式实现新功能；
- 审查代码；
- 在浏览器画布中手动验证功能。

继续开发此功能时，您还会更新存储库说明、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 智能体并创建功能 PR。

## 场景

Tailspin Toys 的游戏目录不断增长，访客需要按类别和发行商筛选游戏。待办事项中的议题描述了功能，但组合类别筛选等细节需要在编写代码前商定。您将使用 Plan 模式确定这些决策，然后授权 Autopilot 在明确范围内实现功能。

## 背景

在开发流程中引入 AI 编码智能体，并不会改变基本原则。事实上，这些原则变得更加重要！大多数开发人员遵循类似的流程：

1. 打开已创建的议题，查看需要完成的工作详情。
2. 制定需要构建内容的计划。
3. 编写并审查代码。
4. 运行测试验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述步骤类似。

遵循这种标准方法，可以确保 AI 生成的代码满足既定需求，并接受与手写代码相同的审查流程。

## 会话模式

**会话模式**决定智能体可以自主执行多少操作。可以在提示输入框下方的下拉菜单中设置，并随时更改：

- **Interactive**：您与智能体协作。智能体提出更改建议，并等待您的输入后再继续。
- **Plan**：智能体先制定计划。它会等您审查并批准后才执行。
- **Autopilot**：智能体完全自主工作——编写代码、运行测试并不断迭代，无需等待输入。

先在 Plan 模式中审查计划，然后使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后选择存储库顶部导航中的 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已有议题，无需重新创建。
2. 选择 **New session**，然后选择基于更新后 `main` 创建的**新工作树**。

   ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果这些命令在终端中可以运行，但会话中不行，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装它。

## 规划筛选功能

规划可以让您在 Copilot 编写代码前审查方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并对照议题的验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏符合条件时如何处理。

计划应使用项目现有工具执行 lint、单元测试、E2E 测试和类型检查。将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。批准前先要求修改计划中的问题，并保留议题 URL 和商定的澄清信息，供后续验证时使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或您所用版本中的相应选项。确认当前模式指示器显示 **Autopilot**。

Copilot 会开始实现功能！您会看到它按照已确定的计划逐步推进、生成代码并运行测试。

> [!NOTE]
> 批准计划后可能会立即开始实现，因此应先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再将检查视为完成。只停止您启动的服务器。

## 审查并验证实现

生成代码后，应像其他代码一样，在合并前进行审查。接下来审查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能的实现和测试。
2. 将结果与议题及已批准的澄清内容进行比较，包括多类别和发行商组合。检查更改是否遵循现有存储库说明。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，且可能复用本地服务器；请确认被测服务器属于此工作树，而不是上一课使用的服务器。

## 探索新功能

代码看起来不错，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动应用并在浏览器画布中打开页面：

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果符合该类别。清除筛选，再选择发行商，确认结果符合该发行商。
4. 组合类别和发行商筛选，并根据议题和已批准的计划比较结果。如果支持多个类别，请验证商定的组合方式。
5. 尝试一组没有匹配游戏的筛选条件，并检查空状态。清除或重置筛选条件，确认完整列表重新显示。
6. 完成后，使用以下提示让 Copilot 停止此会话启动的开发服务器并关闭浏览器画布：

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 为后续课程保留此会话

暂时不要创建或合并筛选功能 PR。保留此会话、工作树和分支，供第 4 至第 8 课继续使用。接下来将把自定义说明应用于筛选代码，再添加技能和 QA 改进，最后在第 8 课创建并合并组合 PR。停止开发服务器后，可以让会话保持空闲状态；下一课会回到同一会话。
