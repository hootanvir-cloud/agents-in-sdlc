GitHub Copilot のエージェントモードでは、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、作業が自分のマシン上でリアルタイムに進むため、すべてのツール呼び出しとファイル編集を確認できます。差分をインラインでレビューし、個々の変更を受け入れたり元に戻したりできます。また、エディターを離れずに追加のプロンプトを送り、作業を調整したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッション中にエージェントの方向を調整し、高コントラストに加えてライトモードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加したいとのことです。新しい会話を最初から始めるのではなく、同じセッションで作業を拡張するようエージェントに依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集などを確認できます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業する間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み込み、編集、実行許可を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度対応させます。
4. チャットの上部にある **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められた場合、エージェントは一時停止して **Allow** の確認を表示します。内容を理解し、許可できるコマンドのみ承認してください。

5. エージェントが高コントラストモードを実装し終えるまで待ちます。変更内容の要約が最後に表示されます。

## ライトモードを追加するようエージェントに依頼する

高コントラストモードができたら、同じ会話を続けてライトモードの切り替えも追加します。同じチャットセッションを続けることで、エージェントはこれまでのコンテキストを保持します。変更したコンポーネント、スタイルの方法、設定をローカルストレージに保存する実装なども把握しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. 高コントラストのときと同じように、新しい編集が表示されるたびにレビューします。各差分で **Keep** または **Undo** を使います。
4. エージェントの方向性が希望と異なる場合、たとえば切り替え UI を意図しない形でリファクタリングしようとする場合は、チャット入力欄の横にある **Stop** ボタンで停止し、要件を明確にする追加メッセージを送ります。

> [!TIP]
> 進行中のセッションを方向付けるほうが、最初からやり直すよりも効率的です。追加プロンプトを使って「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」と調整したり、「切り替えを3つにせず、既存の設定パネルにライトモードを追加する」と修正したり、「両方の切り替えにキーボードショートカットも追加する」と範囲を広げたりできます。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容をまとめて確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたすべてのファイルを確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存などに注目します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向付けました。ファイル編集を確認しながら受け入れたり元に戻したりし、追加プロンプトでコンテキストを失わずに作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり元に戻したりしました。
- 追加プロンプトを使い、進行中のセッションの方向を調整しました。

次の[レッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルカスタムエージェントが作成した変更をレビューします。
